# Game AI flow and platform credential

User authorized implementation, tests, push/merge/deploy without further approval. Supersedes old per-user keys and sample fallback. Targets #126 identity/abuse, #127 idempotent/recoverable rounds and #128 AI answers/hints. New duplicate generation/server-secret tracker will cover history/deployment.

## Design and alternatives
Use one server-owned Gemini credential from GitHub `GEMINI_KEY_2` (fall back to existing `GEMINI_KEY`, then `GEMINI_API_KEY`), delivered privately during API deployment as `Entertainment:Gemini:ApiKey`. Never user-supplied keys, frontend env, repository contents, logs or per-group new key storage. Keep legacy stored encrypted fields for compatibility but ignore their values. Preserve all other application records. Shared provider queue and bounded rate-aware retry are recommended over key rotation. Send bounded recent history (20) and reject normalized full-history exact duplicates plus conservative near-duplicates (case/space/punctuation and same template differing in small tokens). Duplicate retry supplies explicit rejected sentence; exhaustion throws recoverable generation error, never accepts final duplicate. Use deterministic reservation document ID per group+normalized sentence and transaction with round/group state, avoiding unique index migration over legacy duplicates. Persist full history naturally through rounds; reserve new generation and compare legacy history too. No automatic live provider calls in ordinary CI; dedicated manual smoke performs one generation and one evaluation call.

## Shared contracts for parallel work
Keep IGeminiSentenceService.GenerateAsync signature temporarily for compatibility but runtime provider ignores legacy apiKey argument and uses configured server credential. GeminiSentence gains Hints IReadOnlyList<EntertainmentWordHint>(English,Finnish). Existing BaseForms remains compatibility only. Add IEntertainmentAnswerEvaluator.EvaluateAsync(sentenceEn,referenceFi,answer,level,ct) returning correctness, a meaning grade, a Finnish quality grade, a server-calculated round score, corrected answer, explanation and precise changes. The AI returns meaningPoints (0–7) and finnishPoints (0–3); `isCorrect` is true exactly at 7/7 meaning. The server validates both grades and adds them for a 0–10 round score. Partly accurate translations can still earn points. Hints and observer answer reveals never change scores. Show the grade dimensions and total in feedback. Provider schema is bounded and validated, correct alternate answers accepted; no fabricated verdicts. Generation now returns validated English/Finnish pairs. All failures including missing server credential, quota, timeout/malformed output throw safe EntertainmentAiUnavailableException. Caller cancellation propagates. No samples in production for either call.

Player capability: create/join result adds PlayerToken; generate unguessable token once, persist only SHA256 hash on player. Authenticate JoinLobby(groupId,playerId,playerToken), validate constant-time, no raw hash/token in lobby DTO. All actions remain connection-bound. Client stores scoped token for rejoin. Missing legacy tokens require new guest session; do not silently rebind by exposed IDs. Limit room membership, exact create-path rate limiting and per connection/provider quotas.

Domain round adds Hints, RevealedHintIndexes, AnswerRevealed, SubmittedAnswer, Evaluation, IsEvaluated, NextRoundId/transition state and persisted score/turn information as needed. Role-safe payload exposes English hint entries only; Finnish cell text returned only on accepted indexed RevealHint(group,player,index,roundId). RevealHint server emits hintRevealed {roundId,index,finnish} to translator, idempotent per index; observers can receive authorized full answer. RoundStarted DTO adds RoundId and Hints safe pairs (Finnish empty for translator), current replayable feedback and scores via snapshot where appropriate.

Typed hub command CheckAnswer(groupId,playerId,roundId,answer), response event answerEvaluated {roundId,answer,evaluation}; preserve answer and round on failure, allow retry only. NextRound(groupId,playerId,roundId) is allowed only after a valid provider evaluation (correct or incorrect). Feedback remains until explicit Next. No Skip or Done self-report bonus. Points are awarded once from the validated 7+3 rubric and saved with evaluation and group scores in one transaction. Retry never duplicates scores or changes turns. Incorrect answers show correction and why; one graded submission per round, technical retries recover the same result. End/Leave are separate from Next, host can end but must not race generation into reopening.

Hub mutations serialized per group across async awaits (cancellable bounded semaphore) and validate expected round/state inside lock. Reject stale commands. Compute next translator without mutating until generation+durable round save succeeds; errors keep pending state and explicit Retry start/next. JoinLobby sends authoritative current role-safe round, hint reveals, scores, feedback, finished results; reconstruct session from stored group/round/player state on restart. On reconnect explicitly JoinLobby again; pending action errors shown, no permanent spinner. Track presence accurately and skip offline participants; leaving tells server. Host absence must retain recoverable session/allow End after reconnect; avoid implicit host takeover.
